# @deepseek-ai/dsh-helper

[English](README.md) | 中文

## 概述

当快速主模型需要独立的高级模型意见时，启用 `advisor`。每次调用向全新顾问发送明确问题、证据和已尝试的方法，然后把建议返回主模型。可以选择已有 API 模型或可选的本机 Codex 后端。求助会消耗提供方额度；保存设置不会调用模型。

## 使用本包

Codex 咨询通过 `subagent-codex/tool` 在父会话保存工具开始与完成记录；`helper/codex-trace` 将原生线程关联到 advisor 调用或自动咨询。这些审计记录不进入父模型消息。API 咨询继续保留已有子会话日志。只有开始而没有完成的条目表示观察缺口，不代表成功。

此组合挂载默认关闭的 Advisor 服务。security Web 组合还挂载[浏览器控件](../../client/ui-helper/README.zh.md)，并启用 [Codex 求助提供方](../subagent-codex/README.zh.md)。其他配置可以使用 `dsh plugin --profile <name> add @deepseek-ai/dsh-helper` 安装，再显式组合可选 UI 和 Codex 插件。

在“模型”页面配置 API 地址、密钥、协议和模型。Advisor 只保存已有的提供方／模型引用和思考强度。Codex 使用包内固定版本及原生 ChatGPT 凭据；在 `dsh-subagent-codex` 设置 `consultation: true` 即可提供账号与模型接口。初始 Codex 候选是 `gpt-6-astra` 和 `high`；模型必须出现在当前账号目录中。基础组合不会新增 Codex 依赖。

全局 `enabled` 与 `mode` 偏好只用于新建顶层会话，`mode` 默认为 `normal`。`/advisor normal` 与 `/advisor proactive` 为当前会话开启相应档位；`/advisor on` 选择正常档，`/advisor off` 关闭 Advisor。`/helper` 命令继续作为别名可用。会话日志保留所选档位；没有档位字段的旧策略按正常档恢复。关闭后，下一次模型请求移除工具，并拒绝后续调用；已运行的求助使用常规停止按钮取消。模型偏好每次调用只采样一次。不支持的已保存档位会报错，不自动降级。空档位表示明确使用提供方默认；Web 选择模型时优先预选可用的 `high`。

API 咨询每次分析请求使用 `apiMaxTokens`（默认 32,768）。`apiRecoveryEnabled` 默认为 false；启用后，一次交付请求使用 `apiRecoveryReasoningEffort`（默认 `low`）与 `apiRecoveryMaxTokens`（默认 8,192）。两个档位都必须受到所选模型支持；不支持的恢复配置会在推理前失败。Codex 咨询不使用这些 API 设置。

每次调用记录后端、所选／实际模型、档位、终态、耗时和已报告的 token 数。缺失用量保持缺失。Codex 累计通知替换此前总量，缓存输入从 DSH 未缓存输入计数中扣除。API 调用链接到完整子会话。统计来自完整投影，不依赖聊天分页；分支继承的调用不计入，恢复时未结束的调用标记为中断。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

插件组合现有子代理生命周期，不修改主循环。API 提供方在子代理创建事务内强制 native 工具呈现，过滤到当前可用的 `read`、`glob`、`grep`、`read_image`，并使用相同白名单守卫执行。沿用读取权限，不将读取限制在工作区。Codex 使用临时只读线程，禁用网络和提权，并关闭 Apps、插件、hooks、递归代理以及全部有效 MCP 服务。

会话投影只从已记录的策略、开始和结束事件推导。工具调用 ID 将参数与回答关联到指标，包括 PTC 子调用。不发布独立运行时不变量伴随模块：生命周期归子代理服务所有，投影值从唯一事件来源推导。

Host 插件可在已启用的积极模式会话中调用 `consultAutomatically`。自动调用通过 `helper/auto-start` 和 `helper/auto-end` 保存咨询 ID、问题、最终建议和与工具调用相同的指标，复用只读提供方执行和取消路径。自动咨询不能与同一父代理中的其他咨询重叠。提供方失败在子代理清理后返回调用方；清理失败仍为终止性错误。

可选的第五参数 `ApiConsultationOptions` 为本次调用指定完整 API 路由、思考强度、每次请求的输出 token 上限和 `toolAccess`，不改变已保存的偏好或手动咨询。省略时使用已保存后端和只读权限。`toolAccess: 'none'` 只向全新子代理提供提交的证据，隐藏全部工具并拒绝工具执行；`'read-only'` 保留现有读取白名单。父会话记录实际模型与用量；关联的子会话日志记录提供方、模型和输出上限。`recovery` 接受明确的档位和输出上限；省略或传入 `false` 都会禁用恢复，即使已保存的手动 API 恢复设置处于启用状态。

无工具 API 顾问保留继承的系统策略，并在末尾追加职责段：“You are a tool-free adviser for the parent agent.”（你是父代理的无工具顾问。）该段将执行、技能加载、作业管理、进度保存和任务完成交由父代理负责，同时保留授权、安全和证据要求。子代理无需完成这些操作即可返回建议。若完整系统提示或组装覆盖移除了该段，咨询会在模型推理前失败；无工具咨询应使用可组合的提示段。子会话日志记录组装后的系统提示及终止性失败。只读 API 和 Codex 顾问沿用现有指令。

启用交付恢复后，已知输出触顶或正常结束但没有可见正文的响应，可以在同一子会话中追加一个独立轮次。原先不完整的轮次保留在日志中。恢复隐藏并拒绝工具，只发起一次对话请求，要求交付已证实的发现、剩余不确定性和下一项检查。只有恢复轮次正常结束且非空的正文才能成为建议；不得用先前的片段代替。提供方错误、取消和未知结果不会重试。调用方的截止时间覆盖两个轮次，已报告用量也累计两个轮次。

Host 插件可以为持续运行的主代理使用 `installOutputRecovery`。持久化的尝试记录防止重载后重复恢复；调用方选择整个会话一次，或每次新的人类输入被接纳后允许一次。新的人类输入会撤销尚未领取的交付提示。已经领取的交付请求可以结束；之后的人类任务使用正常请求设置与工具。同一领取批次中的人类引导优先于交付指令。

调用方等待控制器的 `dispose()`。禁用恢复会取消其正在进行的交付轮，并将工具守卫保留到该轮结束；无关的排队输入仍然保留。Agent 拥有尚未完成的配置恢复，直到下一个正常请求头提交，包括改用其他模型的请求。在请求头持久化前失败，会保留配置恢复供下次请求使用。清理时不会追加合成的请求头。

</details>

<a id="model-experience"></a>
## 模型体验

### 高级模型求助

#### 模型看到什么

主模型自行完成首次侦查。积极档要求模型在采用会排除候选或决定后续大量工作的前提之前，先执行最小的可运行检查。检查必须区分竞争解释的预测，其预期结果或阳性对照必须有独立依据。工具失败与空搜索不能否定整个解释。`advisor` 工具接收前提、原始证据、实际检查和仍未解决的决定。模型在改变方向之前验证推荐检查，只在有新证据或实质不同的问题时再次咨询。Helper 不计数工具执行或策略，也不追加首工具提醒。其他 Host 插件可以追加已记录的证据执行通知。正常档保留首次侦查后的可选专家咨询。

#### Token 影响

工具说明与提交的证据消耗输入 token。工具返回完整建议或明确失败。可选的交付恢复增加一次输入请求，其中包括可用的前序分析，以及具有独立上限的输出；仅增加 token 上限不保证成功交付。API 顾问可用允许的工具查阅文件；没有工具权限的自动咨询仅使用提交的证据。Codex 顾问可在强制只读沙箱中使用原生文件读取命令。两种顾问均不得递归求助或执行实现修改。

#### KV Cache 影响

每个顾问拥有独立的请求前缀。修改模型、档位或可用工具会改变该前缀。主对话追加提交的调用和返回的建议，不改写之前的消息。交付恢复追加提示，并改变该请求的档位、输出上限和可用工具。切换档位会改变后续请求中的工具说明。

## 已知限制与后续工作
<a id="known-limitations-and-deferred-work"></a>

- 每次求助前台等待。可选的交付恢复只处理已知的不完整输出，不重试提供方失败或切换后端，也不能保证模型回答完整或正确。
- Codex 中间工具活动不形成 DSH 子日志；保留最终建议和已报告用量。
- 调用方提供相关证据。缺少凭据、账号模型不可用和提供方失败会显示为错误。
