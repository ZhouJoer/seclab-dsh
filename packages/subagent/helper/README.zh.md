# @deepseek-ai/dsh-helper

[English](README.md) | 中文

## 概述

当快速主模型需要独立的高级模型意见时，启用 `advisor`。每次调用向全新顾问发送明确问题、证据和已尝试的方法，然后把建议返回主模型。可以选择已有 API 模型或可选的本机 Codex 后端。求助会消耗提供方额度；保存设置不会调用模型。

<a id="use-this-package"></a>
## 使用本包

此组合挂载默认关闭的 Advisor 服务。security Web 组合还挂载[浏览器控件](../../client/ui-helper/README.zh.md)，并启用 [Codex 求助提供方](../subagent-codex/README.zh.md)。其他配置可以使用 `dsh plugin --profile <name> add @deepseek-ai/dsh-helper` 安装，再显式组合可选 UI 和 Codex 插件。

在“模型”页面配置 API 地址、密钥、协议和模型。Advisor 只保存已有的提供方／模型引用和思考强度。Codex 使用包内固定版本及原生 ChatGPT 凭据；在 `dsh-subagent-codex` 设置 `consultation: true` 即可提供账号与模型接口。初始 Codex 候选是 `gpt-6-astra` 和 `high`；模型必须出现在当前账号目录中。基础组合不会新增 Codex 依赖。

全局 `enabled` 与 `mode` 偏好只用于新建顶层会话，`mode` 默认为 `normal`。`/advisor normal` 与 `/advisor proactive` 为当前会话开启相应档位；`/advisor on` 选择正常档，`/advisor off` 关闭 Advisor。`/helper` 命令继续作为别名可用。会话日志保留所选档位；没有档位字段的旧策略按正常档恢复。关闭后，下一次模型请求移除工具，并拒绝后续调用；已运行的求助使用常规停止按钮取消。模型偏好每次调用只采样一次。不支持的已保存档位会报错，不自动降级。空档位表示明确使用提供方默认；Web 选择模型时优先预选可用的 `high`。

每次调用记录后端、所选／实际模型、档位、终态、耗时和已报告的 token 数。缺失用量保持缺失。Codex 累计通知替换此前总量，缓存输入从 DSH 未缓存输入计数中扣除。API 调用链接到完整子会话。统计来自完整投影，不依赖聊天分页；分支继承的调用不计入，恢复时未结束的调用标记为中断。

<a id="understand-the-implementation"></a>
## 理解实现

<details>
<summary>实现细节——点击展开</summary>

插件组合现有子代理生命周期，不修改主循环。API 提供方在子代理创建事务内强制 native 工具呈现，过滤到当前可用的 `read`、`glob`、`grep`、`read_image`，并使用相同白名单守卫执行。沿用读取权限，不将读取限制在工作区。Codex 使用临时只读线程，禁用网络和提权，并关闭 Apps、插件、hooks、递归代理以及全部有效 MCP 服务。

会话投影只从已记录的策略、开始和结束事件推导。工具调用 ID 将参数与回答关联到指标，包括 PTC 子调用。不发布独立运行时不变量伴随模块：生命周期归子代理服务所有，投影值从唯一事件来源推导。

Host 插件可在已启用的积极模式会话中调用 `consultAutomatically`。自动调用通过 `helper/auto-start` 和 `helper/auto-end` 保存咨询 ID、问题、最终建议和与工具调用相同的指标，复用只读提供方执行和取消路径。自动咨询不能与同一父代理中的其他咨询重叠。提供方失败在子代理清理后返回调用方；清理失败仍为终止性错误。

</details>

<a id="model-experience"></a>
## 模型体验

### 高级模型求助

#### 模型看到什么

首次侦查由主模型独立完成，不调用 Advisor。正常档说明此后何时可以咨询专家，不追加进展提醒。积极档要求主模型：同一障碍经过约三种实质不同的策略仍无可采取行动的新证据或进展时，主动求助。每次顶层工具执行后都会追加写入日志的简短进展提醒，`advisor` 本身除外；子代理不接收提醒。模型按策略判断，将相关搜索及其变体合为一组；本服务不自行计数或自动发起咨询。判断停滞后，模型在继续重试、索取更多信息或报告受阻前主动咨询，即使预期顾问也可能无法解决问题。重复报错、增加猜测和没有新线索的扩大搜索均不视为进展。调用时提供问题、证据、已尝试的方法和观察结果，并区分事实与假设。收到建议后，先验证最小的推荐步骤，再继续任务；有新证据或新问题时可再次咨询。顾问收到提交的材料与只读指令。

#### Token 影响

积极档的进展提醒会增加输入 token；正常档与关闭状态均停止追加新提醒。工具返回高级模型的最终文本或明确失败。API 顾问可用允许的工具查阅文件。Codex 顾问可在强制只读沙箱中使用原生文件读取命令。两种顾问均不得递归求助或执行实现修改。

#### KV Cache 影响

每个顾问拥有独立的请求前缀。修改模型、档位或可用工具会改变该前缀。主对话追加进展提醒、提交的调用和返回的建议，不改写之前的消息。切换档位会改变后续请求中的工具说明。

## 已知限制与后续工作
<a id="known-limitations-and-deferred-work"></a>

- 每次求助前台等待；不自动重试或切换后端。
- Codex 中间工具活动不形成 DSH 子日志；保留最终建议和已报告用量。
- 调用方提供相关证据。缺少凭据、账号模型不可用和提供方失败会显示为错误。
