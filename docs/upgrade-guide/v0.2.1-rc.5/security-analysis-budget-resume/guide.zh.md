# 通过用户请求恢复达到预算的安全分析

[English](guide.md) | 中文

## 变更

安全分析先前在每个轮次开始时重置 `analysisTurnTokens`，因此后台完成通知可能在预算收尾后重开探索。内部续行现在保留原有额度及收尾状态。最终回复后，普通内部通知不会再发起模型请求。显式配置的 Helper 输出恢复提示可请求一次无工具交付回合，但不会重开探索。依赖作业完成通知恢复已达到预算的调查的安全部署会受此影响。收尾期间仍可收集或取消当前 Session 所属的已有作业，包括保存成功之后；清理尝试次数受限，详见[包 README](../../../../packages/experimental/security-analysis/README.zh.md)。

方向复查和常规收尾期间始终保留工具定义。如果最终交付因被拒绝的动作停滞，会有一次移除工具的纯文本交付请求，可能使缓存前缀失效；再次无效调用会被有界终止，不会重开探索。执行端实施阶段限制，不反复替换工具列表。集成方不能把工具定义可见视为执行许可。`analysisTurnTokens` 使用实际累计用量，不再根据上一次消耗预测下一请求。恢复时的冷缓存请求未达到阈值就能继续探索；单次请求可能超出阈值。有界保存、清理和最终交付请求仍会消耗额外 token。

## 迁移

1. 保留 `cordis.yml` 中的 `analysisTurnTokens` 和 `analysisWrapUpSteps` 设置，无需更改键名。预算收尾后发送新的用户请求以继续，不再依赖自动完成通知。若部署明确由其他机制负责预算，可用 `analysisTurnTokens: 0` 关闭这层额外探索限制。
2. 调度分析工作的 Host 插件可调用 `securityWorkbench.getAnalysisPhase(agent)`，仅在返回 `exploring` 时允许探索。这是当前进程中的实时状态，不是持久化的任务完成标记。
3. 确认收尾后迟到的作业完成通知不会再次调用模型，而新的用户请求会恢复探索权限和额度。验证被禁止的工具即使定义可见也无法执行。
