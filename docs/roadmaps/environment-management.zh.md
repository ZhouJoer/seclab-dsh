# 安全环境管理方案

[English](environment-management.md) | 中文

## 概述

本方案覆盖 Shell 运行时、语言运行时、本机与交叉编译工具链及容器。Python 初始化已由 [`security:python`](../user/guide/security-analysis.zh.md) 实现。下述通用环境管理仍为设计，尚未交付。复用现有安全环境管理器、工具目录、安装配置和子进程服务；应用仍由 `dsh` profile 启动。

<a id="design"></a>
## 管理设计

区分三种记录：提交到仓库的可移植需求、本机可执行文件选择，以及带时间戳的健康测量。需求描述版本约束、支持的主机架构、安装来源、探测操作和依赖关系。本机选择包含绝对路径与启动参数。测量包含可执行文件身份、版本、架构、依赖结果和诊断；它们是观察，不是安装声明。可移植需求中不提交凭据或工作站路径。

优先使用请求显式选择，其次使用工作区选择和部署默认值。发现操作返回候选；存在多个兼容候选时要求保存选择。显式选择失效时可见地失败，不回退到其他运行时。CLI、UI 与实际执行必须使用同一份解析结果。未来共享解析器必须保留现有仓库/home 优先级和显式 profile 覆盖；改变默认值时提供升级指南。

环境变量只应用到选定的子进程，不全局改写 PATH。Java 选择提供匹配的 `JAVA_HOME` 与命令路径。MSVC 使用对应的开发者环境、SDK、编译器和链接器。交叉工具链选择记录主机架构、目标 triple、sysroot、ABI、编译器及链接器版本和运行库。区分主机编译、目标编译与目标执行；生成 ELF 文件不代表可在设备执行。

发现和健康检查保持只读。初始化必须显式触发，使用可信来源、有界子进程和固定依赖版本。安装新一代环境、验证成功后，再原子发布选择。保留前一代环境以支持回退和活动任务。垃圾回收必须拒绝删除任务正在引用的环境，并作为独立的显式操作。离线或不支持的目标应给出可操作错误，不静默替换工具。

<a id="acceptance"></a>
## 实施与验收

1. Python：显式独立基础解释器、隔离依赖、失败保留旧配置，以及 CLI/profile 配置一致性。验证新克隆、重复初始化、安装失败、无效解释器和并发操作者编辑。
2. 只读盘点：在现有定义中增加 Shell、Node、Java 和本机构建探测。显示选择来源与冲突；验证发现操作不修改设置、不启动容器。
3. 使用方接入：将解析后的环境传递给既有子进程 provider。验证 Shell 命令和适配器观察到同一选定运行时，包括 Java 和 MSVC 环境变量。
4. 交叉编译：只接入需要的目标系列。编译并链接最小程序，检查目标文件头，记录未解决的硬件或许可证条件。使用测试自有临时目录，不依赖物理设备。
5. 复现：在声明支持的 Windows、Linux 和 macOS 上验证，覆盖空格及 Unicode 路径、缺失工具、失效路径、网络失败和并行初始化。使用隔离的 home，在每个准备失败路径保留活动环境。

<a id="dev-note"></a>
## 开发备注

本方案不声称所有运行时都有可移植的自动安装程序。厂商授权、具体目标系列与离线包镜像需要在实现前明确操作者需求。安装归档和构建依赖的哈希锁定属于后续工作；Python 当前固定运行依赖版本，并验证安装后的环境。
