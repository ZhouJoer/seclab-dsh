# 本地方向复核

[English](README.md) | 中文

## 摘要

在用研究前提排除候选或扩大搜索之前，对照原始观察核对该前提。分别记录观察与解释，请求有界独立复核，并在进展交接中保留不确定性。复核可以提出可执行检查，但不认证科学结论。

这个私有文件插件可选启用，默认关闭，不属于发布的工作区包或内置 profile。目录保留本地研究布局；版本化文件仅包含通用机制和合成测试，不含任务记录或部署设置。

<a id="local-mounting"></a>
## 本地挂载

本地部署通过已有 `dsh` profile 将 [index.mjs](index.mjs) 挂载为文件插件。启用需要设置 `enabled: true` 和绝对路径 `workspace`；仅匹配的顶层主会话适用。profile 必须提供注入服务和配置的模型路由。部署专用 profile、凭据和工作区路径不得纳入版本控制。私有清单不是 npm 安装目标，也不是工作区成员。

[link-local-dependencies.ps1](link-local-dependencies.ps1) 在 Windows 上链接当前检出目录中已构建的依赖。它核对已有目录联接的目标并拒绝冲突项。依赖链接保留在本地。[delivery.mjs](delivery.mjs) 是另一个可选的主输出限制与恢复插件；[对应说明](delivery.README.md) 描述其策略。两个入口都不直接启动应用。

入口模块中经过验证的 `Config` 导出定义可用设置与默认值。复核路由、推理档位、输出上限、来源字节限制、工具类别和咨询预算均可配置。启用路由不会提供凭据，也不代表获准发送私有材料。

<a id="research-workflow"></a>
## 研究流程

先直接运行最小区分性检查。普通观察、安装命令、目录操作和工具次数本身不要求顾问介入。当后续操作采用某个前提时，通过 `premise_check save` 或 `submit` 同时登记 `pendingDecision` 和 `dependentOperation: {name, arguments}`。只有精确匹配的已登记操作受到门禁控制，不同登记操作分别保留决定。

`save` 使用观察、解释和下一检查记录进展；`prepare` 预览相同记录但不保存；`submit` 记录两种解释、预测结果及已经执行的检查。没有操作绑定的普通检查点是未验证交接。保存回执、模型的支持判断和工具调用完成均不代表科学有效性已成立。

默认自动复核针对即将指导后续配置内操作的实验公开解释。材料包含可重建的生产代码、实际输出、解释和下一操作。`automaticInterpretationSignals` 默认为 `[]`，因此资格不依赖固定词；仅显式配置非空列表时才按措辞筛选候选。可选的 `before-execution` 阶段在执行前核对适用的生成脚本。尾部带正整数参数的 `Out-String -Width` 作为格式元数据保留生产命令关联，不认证测量有效性。

已记录的 Python 命令可以包含字面选项 `-X utf8`。主模型准备写入或编辑分析脚本时，如果紧邻的解释引用了已完成实验的调用 ID、结果序号或输出原文，即使缺少独立来源观察，也可发起复核。复核材料会标明缺少的输入，供顾问判断该测量能支持多大范围的推断。

具体的 `check-required`、`insufficient-evidence` 或仅建议结果会阻止被审操作。独立检查和无关观察继续经过正常权限流程。限制或交付不完整造成的自动覆盖缺口保持 `unreviewed`，普通未登记操作仍可执行；已知疑点和显式登记保留更严格的门禁。建议不能绕过另一项操作的登记。

<a id="evidence-and-delivery"></a>
## 证据与交付

原始工具结果附带简短且已记录的来源句柄。`callId`、结果序号和工作台证据 ID 解析到实际记录的调用；定位参数是不可信的导航数据。`inspect` 可选使用，在不新增模型请求或复制完整输出的情况下提供引用诊断。无效引用保留明确诊断，不能成为已完成证据。

执行回执描述宿主观察到的完成、退出状态、取消、超时和输出完整性。进程成功退出不能证明每个子步骤或测量有效。失败、截断、外置省略或不可用的来源保留其限制。当前用户请求中已执行的实验，只有在生产命令明确引用可信资产映射中的相同资产 ID 或无歧义绝对路径时，才能检索旧原生观察。这些来源标为 `previous-request`，既不继承旧复核许可，也不证明输入文件保持未变。

复核接受一个完整 JSON 对象，或一个完整 JSON 代码块后附普通说明。多个候选、截断、缺少必需字段及无效引用不能被静默修补为成功。可用的拟议检查在执行和评估前仍只是建议。

最终交接复核核对公开答复的确定性。材料优先保留明确引用和近期检查，再在预算内按带名称的数值字段、摘要值和其他字面值查找早期输出。即使答复只写出摘要前缀，也可用它找回含完整摘要的原始观察。顾问仍须核对当时实际比较了什么。需要时，宿主保留原答复并追加关联来源的更正或明确的未复核通知。完成复核另行根据原始目标检查完成声明，再决定是否保存。

<a id="limits-and-lifecycle"></a>
## 限制与生命周期

咨询共享每个用户请求的次数、token 预留、间隔及取消管理。内部恢复不会重置花费。新的真实用户请求重置额度；插话改变可用证据而不清除已产生的成本。最终交接预留咨询容量，但预留不保证成功交付。未知用量按预留保守计入，不表示已确认的账单。

探索阶段至少有两个复核名额时，`reserveInterpretationCall`（默认 `true`）会让未引用实测结果的自动解释复核保留最后一个名额。引用实测结果的脚本决策、显式登记的决定或完成检查仍可使用该名额，同时受共享 token 预算和时间间隔约束。

顾问没有工具。closing 和 finalizing 阶段禁止新研究咨询，同时允许指定的交接流程。取消、新用户输入和插件卸载停止所拥有的工作，防止晚到建议授权旧操作或写入旧更正。去重依据已记录的用户请求、来源版本、决定和结果。

<a id="validation"></a>
## 验证

在仓库根目录运行合成测试：

```sh
pnpm run test:local-direction-review
```

专用配置解析工作区源码导入，使用模型与执行器夹具运行真实 Cordis Loader、AgentLoop 和 Helper 组合。阻断式 CI coverage 和普通 unit 聚合均包含此命令；运行它不会联系模型服务商，也不会在用户 profile 中启用插件。测试工件继续被忽略。

`.mjs` 实现及这些单独配置的测试不在仓库 TypeScript 构建或包源码覆盖率阈值内。构建通过不代表本插件已经类型检查。部署还须核验已构建依赖解析和所选 profile；服务商实际效果需要另行授权的真实模型评估。

<a id="known-limitations"></a>
## 已知限制

插件不能推断所有隐含前提、解析任意 shell 程序或观察未记录的文件修改。配置的解释信号与精确操作匹配可能遗漏语义等价情况。来源选择和有效 JSON 不能证明实验或解释正确。合成测试衡量机制行为，不代表研究任务已经解决。

版本控制只接纳显式列出的源码、测试和文档文件。本地 profile、验证报告、研究日志、原始会话、凭据、生成工件和依赖链接继续被忽略，不要强制添加。
